# 07 — Pass / Fail QA Rubric

**Role:** Binary QA decision framework — use as a reviewer checklist  
**Owner:** eCommerce Operations / Content Governance  
**Status:** Active  
**Audience:** QA reviewers, training, audits

---

## Section 1: Structure (Pass / Fail)

- ☐ Product Name present and formatted correctly
- ☐ Description present (2–4 sentences)
- ☐ Features section present (bulleted)
- ☐ Applicable Features section present
- ☐ No extra sections or headers

**FAIL** if any box is unchecked.

---

## Section 2: Product Name (Pass / Fail)

- ☐ Brand + style name only
- ☐ No colors included
- ☐ No marketing language

---

## Section 3: Description Quality (Pass / Fail)

- ☐ SEO-focused language used
- ☐ Describes product clearly without images
- ☐ Intended use stated or implied
- ☐ Includes model-specific or trademarked features when available
- ☐ No filler or hype language

---

## Section 4: Features Bullets (Pass / Fail)

- ☐ 6–12 bullets
- ☐ Each bullet is verifiable
- ☐ No invented technologies
- ☐ No vague filler bullets
- ☐ Bullets add meaningful information

---

## Section 5: Applicable Features (Critical — Pass / Fail)

- ☐ Only uses exact values from approved master list
- ☐ No synonyms or paraphrasing
- ☐ No features invented to hit a count
- ☐ Slash-separated formatting
- ☐ "None" used when appropriate

**ANY violation here = AUTOMATIC FAIL**

---

## Section 6: Global Checks (Pass / Fail)

- ☐ No color mentions anywhere
- ☐ No inferred materials or tech
- ☐ Description and Applicable Features are clearly separated in intent
- ☐ Output is reusable across retailers

---

## Final Result

**PASS** → Ready for PDP / PIM system ingestion  
**FAIL** → Must be corrected before publishing
